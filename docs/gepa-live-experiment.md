## Validation boundary correction — body-content-v2

A validation-only source/output audit found that the previously recommended candidate changed site weather labels, form text and buttons. A Denver replacement expanded “51°” into a promotional paragraph; the LLM fidelity gate passed it. This defeats the intended mechanical protection even when the aggregate P1 increases. [Replay audit](../verification/gepa-boundary-audit-v1.json): five of eight historically applied selection proposals contain edits forbidden by the corrected boundary. Historical metrics and prompt records remain intact, but that recommendation does not qualify under the new harness. The model default has been restored to unchanged baseline v7.

The corrected `body-content-v2` boundary uses retained DOM provenance to protect site headers, navigation, forms and controls. Article headers inside `main`/`article` remain editable. Because the upstream parser discards some ancestor and paragraph ARIA roles, a query-independent metadata overlay resolves protected roles from the original DOM using the pinned parser’s path recipe. It preserves all upstream blocks, text, Markdown, chunks, source identity and scorer inputs. Mixed/uppercase role tokens and inline controls are protected too. No HTML execution or fetch is involved. Required nullable output slots, provider schema and server validation share this boundary. Ordinary telemetry and new run manifests record its version. Promotion rejects historical recommendations with missing or outdated boundary versions, preserving their artifacts for inspection.

The [seed-2 terminal record](../verification/gepa-run-89090b25.json) stopped at 38 attempts after this audit, with all completed outcomes retained. The agent requested the stop to avoid further calls under the known defective boundary; `user_stop` is the endpoint’s generic manual-stop code. It was not a user pause of the goal. Future qualification requires a fresh baseline and candidate evaluated together under the corrected boundary; no test-page output enters reflection or this fix. Fresh trial `3a27d781574445ef97048804f4ff47d4` freezes `body-content-v2` with the same data roles, baseline, gate and reflection instructions as seed2; it is in progress.

Verification: 138 backend tests passed, two opt-in checks skipped. Regressions cover header/weather protection, controls, paragraph/ancestor ARIA roles, inline role normalization and whole-proposal rejection of a protected target. Both Spec and Standards reviews found no further defects. The [fresh five-record offline parity audit](../verification/gepa-boundary-parser-parity-v1.json) matched saved upstream core parser fields exactly; semantic feature differences stayed at or below `1.19e-7`, with zero provider calls.

This is conservative source provenance protection, not complete factual verification: semantically unmarked JavaScript controls can escape classification, and a header outside `main`/`article` may contain legitimate editorial text that is now read-only. Fidelity judgments remain fallible. No new superiority claim follows from this correction.

## Remaining limits

The frozen v7 context-feature training/serving mismatch remains deliberately deferred under upstream issue #15. Model stochasticity and two already exposed P1-test hosts limit dogfood conclusions. The agreed 100-attempt cap may permit fewer than two fully evaluated challengers; incomplete selection vectors cannot be ranked or promoted.
